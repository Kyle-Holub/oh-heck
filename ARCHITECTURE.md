# How Oh Heck! is put together

A map for anyone changing the game. The README covers playing and building it; this covers
where things live, how they connect, and the tools around them.

## Modules

| Module | What it is |
|---|---|
| `core` | Everything shared: the rules (`rules` package, plain Java) and the game itself (`ohheck` package, libGDX). |
| `android` | The Android launcher, icons, signing. The app the phone runs. |
| `lwjgl3` | The desktop launcher (the Windows jar) and `ScreenshotLauncher`, the scripted screenshot run CI uses. |
| `core/src/arena` | The arena: bots against bots, for measuring AI changes. Not part of the game. |
| `tools` | Python scripts that generate the art, fonts and icons in `assets/`. |

## The rules: `core/src/main/java/rules` (no libGDX)

Everything here runs and tests without a screen.

- `Match` is a whole game: hands, bids, tricks, scores, whose turn, and its own save
  format (`save()` / `load()`). Moves are made with `placeBid` and `playCard`; anything
  illegal throws.
- `Rules` has the scoring and legality checks; `HandOrder` says which way the 8 hands run.
- `TableView` is what a player may know at a moment (`Match.view(seat)`). Bots decide from
  it alone.
- Bots: `Bot` (`Bot.of(level, rng)`), `EasyBot` (Normal with slips), `NormalBot`
  (bids from the learned `BidTable`, plays with card memory), `HardBot` (Monte Carlo over
  imagined deals). `StyledBot` adds a habit (`Style`) on top of any of them.
- `Player` is the roster of twelve: name, level, style, trait, and a **permanent id**.
  Look players up with `Player.byId`, never by position. Never renumber or reuse an id,
  because saves and statistics refer to players by id. `Player.draw` seats a table, using
  the difficulty setting's odds.
- `SavedGame` is a game in progress plus its difficulty and table, as one text.
- `Stats` holds your statistics by difficulty, saved one `name=value` line per number.
- `BidTable` is generated by the arena (`learn`). Don't edit it by hand.

## The game: `core/src/main/java/ohheck` (libGDX)

- `OhHeckGame` owns the shared things (sprite batch, `Assets`, `Audio`, `PostProcessor`,
  `Settings`, `Stats`), the screens, and the back stack (`open` / `back`). Long-lived
  screens are made once through `kept(...)`; the table (`PlayScreen`) is made per game.
- `BaseScreen` is the base for every screen. It provides the 800×480 world stretched to the
  screen's shape, touch handling (`tap`, `drag`, `touchDown/Up`), fonts (`ui`, `serif`),
  frames and buttons, the gold bid numerals (`numeral`), and `stateTag()` for the
  screenshot run.
- `Assets` loads every texture and font. Each loader registers what it makes, so
  `dispose()` releases everything.

### The table

- `TableFlow` is the table's state machine:
  `SHUFFLE → DEAL → TURN ⇄ TRICK → HAND_END → RESULTS → (SHUFFLE | GAME_OVER)`. It drives
  the bots, holds the timing, and calls a `Listener` (the screen) when things happen. It's
  tested in `TableFlowTest`.
- `PlayScreen` is the table screen. It holds the game, your input (taps, dragging a card),
  the pause menu, saving, statistics, and it composes each frame from:
  - `TableDrawing`: counters, trump card, players' panels, your hand.
  - `TrickView`: the trick in the middle. `DealAnimation`: the deal.
  - `TableOverlays`: bid panel, hand results, game over, the menu, hints.
  - `TableLayout`: where everything goes, for the current screen shape.
  - Effects: `Sparks`, `Fireworks`, `Motes`, `Glints` (the trump sparkle), `TableToss`
    (cards thrown off at the end). `GameEnd` orders the ending (cards, then fireworks,
    then scores) and is tested in `GameEndTest`.
- `PlayerPanel` draws a player's placard. `Counters` draws the hand tally and the bid
  tracker; it's shared with the tutorial.

### Other screens

`TitleScreen` (with `FallingCards`, the 3D shower), `TutorialScreen` (How to play: 13
timed scenes, a tap each), `OptionsScreen` (setting rows are `Row` objects), `PlayersScreen`
(the Roster), `HighScoresScreen` (plus the Statistics tab). Scrolling lists use `Scroller`.

### Saving

`Settings` wraps the device's preferences: options, the saved game (`SavedGame`, one
text), statistics, high scores and the tutorial flag. Every format reads its older versions;
the tests in `SavedGameTest`, `StatsTest` and `SaveTest` cover them. Keep it that way when
changing a format.

## Randomness

`PlayScreen` uses separate random streams for seating, the bots and the deck
(`PlayScreen.stream`). A change that draws more random numbers from one stream leaves the
others alone, so the screenshot run's seeded game stays the same game. If a change does
alter that game (new players, new bot behaviour), find a new seed where the scripted player
wins (so the fireworks show) by replaying the rules with the same streams, and update
`ScreenshotLauncher`.

## The screenshot run

`lwjgl3/src/main/java/ohheck/lwjgl3/ScreenshotLauncher.java` plays a seeded game with a bot
in your seat (`Autoplay`), at fixed time steps, and saves a picture the first time each
wanted state appears:

- `WANTED` lists state prefixes, as screens report them in `stateTag()` (for example
  `options`, `tutorial:8`, `bid:3`, `gameover`).
- `settleFrames` sets how many frames to wait in a state before capturing it.
- The screens' `autoplayHuman` branches move the run from screen to screen. The order
  is title, high scores, statistics, options, roster, tutorial, then the game.
- `./gradlew lwjgl3:screenshots -Pshots=options,tutorial` captures only those and stops.
  On CI, add a line starting `[shots: options,tutorial]` to the commit message.

## CI (`.github/workflows`)

| Workflow | When | What |
|---|---|---|
| `tests.yml` | every push | rules and table tests, and the desktop build |
| `preview.yml` | `feature/**`, `refactor/**` | the screenshot run, put on a private draft release `preview-N` (newest three kept) |
| `android.yml` | `develop/**` | signed APK published as pre-release `dev-NNNN` (Obtainium picks these up; newest three per branch kept), then the desktop jar and screenshots attached |
| `arena.yml` | by hand only | arena experiments, deliberately kept off the build |

## Branches and releases

Work happens on `feature/…` or `refactor/…` branches (previewed), and is merged into
`develop/alpha-X.Y.Z` (published as dev builds). A release is a `release/alpha-X.Y.Z` branch
cut from develop, with develop merged into `main`. Then the next `develop/` branch starts,
with `OhHeckGame.VERSION` bumped.

## The arena

`./gradlew core:arena -Parena="<experiment> N"`:

| Experiment | What it does |
|---|---|
| `levels N` | the levels against each other |
| `vs N` | head to head |
| `learn N` | regenerates `BidTable.java` |
| `effort N` | Hard's strength at half, normal and double thinking |
| `players N` | each of the twelve against three plain Normal players |

Duplicate deals rotate seats, so luck cancels out. Run it after any AI change.

## The art

`python3 tools/make_art.py` regenerates the images in `assets/images`. It needs Pillow,
NumPy, the DejaVu fonts and TeX Gyre Pagella (the bid numerals). Court cards come from
`tools/court_art.py`. `make_fonts.py` and `make_icon.py` make the bitmap fonts and the app
icon. The generated files are committed, so regenerate them and commit the results together.
